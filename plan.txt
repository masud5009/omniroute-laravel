PHASE 1: [COMPLETED] EXACT PROMPT RESPONSE CACHING (Speed & Cost Booster)
================================================================================
Goal:
Serve repeated deterministic prompts (<5ms latency) without calling external AI 
APIs, saving 100% of the token cost.

Key Components:
1. Database & Configuration:
   - Add toggle in Smart Combos or Gateway Settings: `cache_enabled` (boolean), `cache_ttl_seconds` (integer, default: 3600).
   - Support cache bypass header (`x-bypass-cache: true`) or skip for `temperature > 0` unless explicitly forced.

2. Backend Implementation:
   - Create `App\Services\Gateway\ResponseCacheService`:
     * Generate deterministic SHA-256 cache key from: requested model, normalized messages array, and temperature.
     * Support streaming playback (SSE replay) and non-streaming JSON responses.
     * Track cache hits vs misses in telemetry.

3. Controller & Gateway Integration:
   - Integrate into `GatewayController` and `OmniRouterService`:
     * Before dispatching to downstream AI providers, check `ResponseCacheService::get($cacheKey)`.
     * On Hit: Return cached response immediately with header `X-OmniRoute-Cache: HIT` and latency <5ms.
     * On Miss: Dispatch request, stream/capture response, and store in cache via `ResponseCacheService::put()`.

4. Dashboard & UI:
   - "Clear Gateway Cache" button in the admin sidebar will actually purge all cached responses.
   - Show "Cache Hit Rate" indicator on the Live Playground telemetry card.

Acceptance Criteria:
- Same prompt sent twice returns a cache hit on the second call in <10ms.
- Streaming responses are faithfully cached and replayed chunk-by-chunk or as instant stream.
- Zero extra external tokens billed on cache hits.

PHASE 2: [COMPLETED] COST & BUDGET SPEND TRACKING (Financial Analytics)
================================================================================
Goal:
Calculate the exact dollar ($USD) cost of every prompt and calculate the exact
money saved by OmniRoute's Prompt Compression and Caching.

Key Components:
1. Database Schema:
   - Add pricing columns to `ai_providers` or `model_pricing` table:
     * `model_pattern` (e.g., "deepseek/*", "gemini-1.5-flash", "gpt-4o")
     * `input_cost_per_million` (decimal 8,4)
     * `output_cost_per_million` (decimal 8,4)
   - Update `gateway_logs` table:
     * `cost_usd` (decimal 10,6) - Actual money spent on the request.
     * `cost_saved_usd` (decimal 10,6) - Money saved by compression & cache hits.

2. Backend Implementation:
   - Create `App\Services\Gateway\CostCalculatorService`:
     * Match model pattern against pricing catalog.
     * Calculate cost based on `prompt_tokens` and `completion_tokens`.
     * Calculate savings based on `saved_tokens` from `PromptCompressor` and cache hits.

3. Dashboard UI:
   - Update Overview & Telemetry pages:
     * "Estimated Spend (USD)" metric card (Today, Last 7 Days, This Month).
     * "Total Money Saved ($USD)" metric badge showing prompt compression ROI.
     * Per-request cost column in Telemetry Logs table.

Acceptance Criteria:
- Every gateway request logs its exact estimated cost in USD.
- Total savings from prompt compression and cache hits are clearly visible in the UI.

PHASE 3: [COMPLETED] UNIVERSAL PROVIDER ADAPTERS (Anthropic & Gemini Native Translation)
================================================================================
Goal:
Allow client applications (Cursor, Cline, LangChain, etc.) to send standard OpenAI 
format requests, while OmniRoute translates payloads on-the-fly to native Anthropic 
(`/v1/messages`) or Google Gemini (`:generateContent`) APIs.

Key Components:
1. Architecture & Driver Pattern:
   - Create `App\Services\Gateway\Adapters\ProviderAdapterInterface`:
     * `formatPayload(array $openAiPayload): array`
     * `formatHeaders(string $apiKey): array`
     * `parseResponse(array $rawResponse): array`
     * `transformStreamChunk(string $chunk): ?string` (Converts Claude/Gemini SSE to OpenAI format)

2. Drivers to Implement:
   - `OpenAiAdapter`: Default passthrough for OpenAI-compatible providers.
   - `AnthropicAdapter`: Translates system prompts, messages array, and tool calls to Claude format.
   - `GeminiAdapter`: Translates messages to `contents` (`user`/`model` parts).

3. Router Integration:
   - `OmniRouterService` detects provider `format` attribute (`openai`, `anthropic`, `gemini`) and automatically delegates to the appropriate adapter.

Acceptance Criteria:
- Sending an OpenAI-formatted request to `anthropic/claude-3-5-sonnet` or `gemini/gemini-1.5-flash` succeeds seamlessly.
- Streaming responses from Anthropic/Gemini are streamed back to the client in standard OpenAI SSE format.

PHASE 4: [COMPLETED] GRANULAR RATE LIMITING (RPM & TPM per Gateway Key)
================================================================================
Goal:
Prevent abusive scripts or runaway agents from exhausting downstream provider 
quotas by enforcing Requests-Per-Minute (RPM) and Tokens-Per-Minute (TPM).

Key Components:
1. Database Schema:
   - Add to `gateway_keys` table:
     * `rpm_limit` (nullable integer, e.g. 60 requests/minute)
     * `tpm_limit` (nullable integer, e.g. 100,000 tokens/minute)

2. Backend Middleware / Service:
   - Create `App\Http\Middleware\EnforceGatewayRateLimits`:
     * Uses Laravel's Cache / Token Bucket RateLimiter (`RateLimiter::attempt`).
     * Returns standard HTTP 429 Too Many Requests with headers:
       `x-ratelimit-limit-requests`, `x-ratelimit-remaining-requests`, `retry-after`.

3. Admin UI:
   - Add RPM and TPM inputs inside the "Create / Edit Gateway Key" modal in the dashboard.
   - Show active rate-limit status badges next to each key.

Acceptance Criteria:
- Exceeding RPM triggers a clean 429 JSON response with `retry-after`.
- Rate limiting operates independently per gateway virtual key.

PHASE 5: [COMPLETED] PII REDACTION & DATA GUARDRAILS (Privacy & Security Masking)
================================================================================
Goal:
Automatically redact sensitive personal identifiable information (PII) like API keys,
credit cards, emails, and passwords before sending prompts to external AI models.

Key Components:
1. Configuration & Pipeline:
   - Add `pii_redaction` option to Smart Combos prompt compression pipeline.
   - Support selective rules: `emails`, `phone_numbers`, `credit_cards`, `api_keys_tokens`.

2. Backend Service:
   - Create `App\Services\Gateway\DataGuardrailService`:
     * Fast regex pattern scanner outside markdown code blocks.
     * Replaces sensitive data with tags: `[REDACTED_EMAIL]`, `[REDACTED_API_KEY]`, etc.
     * Logs count of redacted items in `gateway_logs`.

3. Admin UI:
   - Add `pii` checkbox option alongside `dedup`, `lite`, and `caveman` in the Smart Combos builder modal.

Acceptance Criteria:
- Prompts containing sensitive keys or emails have those items redacted before hitting the external provider.
- Markdown code snippets and code logic remain uncorrupted.

================================================================================

or all keys for a provider enter rate-limit cooldown.

Key Components:
1. Configuration & Settings:

       - On Account 429 Cooldown

2. Backend Notification:
   - Create `App\Services\Notification\AlertNotificationService`:
     * Dispatches async webhook payloads with rich formatting (embed color: RED for down, AMBER for cooldown).

Acceptance Criteria:
- Triggering a 429 or provider failure immediately sends a rich notification to the configured Discord/Telegram channel.
